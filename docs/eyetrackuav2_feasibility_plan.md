# EyeTrackUAV2 接入可行性与实施方案

核验日期：2026-10-16（Asia/Shanghai）。适用项目：`/home/xiaohan/BiSTAR-Benchmark`，当前开发分支 `dev`。

## 1. 结论与验证边界

**技术上可行，且适合作为现有中心伪 ROI 实验之后的真实眼动验证数据集。** 最适合验证的主张是：在给定实际码率下，BiSTAR / BiSTAR Atlas 是否能够提高真实注视区域的视觉质量，以及收益在注视移动、注视延迟和不同观看条件下是否保持。

它不是闭环无人机操控数据。本研究应表述为“无人机视频中基于真实眼动回放的关注区域保真验证”，不能据此直接宣称抓取成功率、飞行控制稳定性、避障成功率或闭环操作效率提高。眼动来自观看原始刺激视频，压缩后观察者是否会改变注视位置也没有在该数据中重新测量。

本次已核验官方论文、作者页面、FTP目录与README；没有下载完整数据集，没有开展EyeTrackUAV2编码实验。视频文件与眼动刺激的逐序列配对仍是接入前置条件。

并已读取一个TASK原始CSV的前4KB：`DTB70_Basketball_subj_10_TASK_OrigRes_DomEye.csv`。样例为无表头、逗号分隔、13列，起始frame_id为1、播放器时间从1 ms开始，起始行眼坐标为`NaN`。这些事实仅针对已检查样例，不推断全部序列都相同。

| 能力 | 现状 | 接入要求 |

因此，这不是只修改数据集YAML即可完成的接入。现有搜索、指标、报告框架可以复用，主要新增的是数据转换、有效性处理、观察者索引、几何/时间映射和实验协议。

## 4. 数据转换与对齐

### 4.1 优先使用原始视频坐标分支

README定义`RAW_DATA_OrigRes_DomEye`为13列，依次表示：

```text
frame_id, player_time_ms, tracker_time_ms,
x_left, y_left, x_right, y_right,
x_binocular, y_binocular, button_flag,
dominant_eye, x_dominant, y_dominant
```

`dominant_eye=1`表示左眼，`2`表示右眼。这些坐标已经位于原始视频帧坐标系。不要再使用1920×1080显示器尺寸归一化，也不要再次减去屏幕居中显示偏移。

已检查样例无表头，加载器不能直接把第一行当字段名。首帧出现`NaN`也说明必须先实现眼动有效性策略，不能仅对官方文件做列重命名后送入当前要求每帧有效的ROI读取器。

以Dominant分支作为首轮固定协议，并用Binocular作敏感性对照；不根据结果临时选择表现更好的眼睛。保留原始左右眼和有效性，记录实际使用的眼睛与回退来源。

### 4.2 时间与帧号

- 先核对每个序列的原始frame_id起点、末尾及播放器时间，不预先假定所有文件都零起点或一基。
- 原始frame_id、播放器时间、tracker时间、源刺激帧与预处理输出帧全部保留。
- 原始30 FPS作为正式主协议；15 FPS只用于工程验证和与旧实验的受控对照。
- 输出帧必须通过实际时间戳/保留源帧索引匹配眼动，不简单采用“输出第k帧等于原始第2k帧”的规则。
- 编码侧若模拟反馈延迟`d`，在时刻`t`只能使用`player_time <= t-d`的最近有效样本。不能使用未来样本或完整fixation结束后计算的中心作为实时输入。
- 离线评价可以利用当前帧完整眼动或官方热力图作为评价真值，但这些数据不能反向输入当前帧编码决策。

特别注意：1000 Hz数据不应盲目对整帧内所有坐标求平均；眼跳期间的平均点可能落在实际未注视的位置，整帧平均还可能引入编码时尚不可用的样本。

### 4.3 几何变换

第一阶段可沿用224×224流程验证格式，但不把强制拉伸后的结果作为唯一正式证据。推荐正式224尺度实验使用保持宽高比的letterbox，并保存实际整数缩放尺寸与padding：

```text
x_out = sx * x_video + pad_left
y_out = sy * y_video + pad_top
u = x_out / 224
v = y_out / 224
```

`sx`、`sy`由实际取整后的缩放尺寸计算。ROI和热力图采用同一几何变换。指标只评价有效图像内容，selector不得把纯padding当作有用patch，不能让黑边提高全画面质量分数。

原图中的小目标缩到224后可能小于一个patch。这是当前模型对该数据的明显局限。高分辨率结果需单独规划，不能直接把配置的image_size改成448或1280而沿用相同位置编码/权重，也不能把切块MAE当作已经实现的完整视频模型。

### 4.4 无效样本

识别缺失、非数值、越界、眨眼/追踪失效，具体哨兵值必须由文件样例和采集说明确认。不要把所有坐标0都视为无效，也不要将越界坐标直接夹到边缘。

建议保留所有视频帧和实际传输时长；控制侧短时保持最近有效注视，超过预先设定的时限切换到固定回退策略。评价侧无有效眼动时将注视质量记为缺失并报告有效率，不能伪造中心注视。当前严格CSV接口需要为这条协议增加`gaze_valid/roi_valid`支持。

## 5. 观察者、ROI与指标协议

### 5.1 观察者维度

同一视频不同观察者的gaze不应混放为同一frame的不同ROI行，否则当前读取器会报冲突。兼容导出可采用：

```text
sequence_id = DTB70_Basketball__TASK__S01
video_id = DTB70_Basketball
observer_id = S01
condition = TASK
source_group = 原始视频或场景分组
```

后四个维度保存到索引和元数据；共享视频帧以`video_id`缓存。相同视频、不同观察者的H.264/H.265输出与眼动无关，应只编码一次，再逐观察者评分。

当前最小兼容ROI CSV仍为：

```csv
sequence_id,frame_id,roi_id,x0,y0,x1,y1,gaze_x,gaze_y,provenance
DTB70_Basketball__TASK__S01,0,gaze_roi,...,...,...,...,...,...,eyetrackuav2_task_dominant
```

此处省略号只表示待转换的实际数据，不是可以运行的样例标签。正式来源不得使用`example_*`，同时必须保留原始文件SHA256和映射信息。

### 5.2 个人注视与群体热力图分开

主实验采用“单观察者注视作为编码输入，评价其当前注视区域质量”。FV与TASK分开报告，TASK作为贴近远程视觉监视的主要条件。

官方多观察者热力图适合用作离线加权评价或单独的群体注意实验。若把同帧全体观察者热力图直接提供给编码器，应明确标为离线真值引导上界，不能宣称是单操作者实时可获得的输入。

FV与TASK是不同人群，条件差异应采用独立组设计。若比较群体注意泛化，可采用留一观察者热力图评价，并单独标明其研究问题；不能把该结果混成个性化注视传输结果。

### 5.3 推荐指标

沿用ROI PSNR、SSIM、normalized L1、关键patch保留率、真实可见覆盖率，同时新增：

- gaze加权MSE/PSNR与SSIM；权重按帧归一化，使用未量化的热力图或明确记录的官方图像权重。
- 注视质量P10/最低若干分位，避免均值掩盖眼跳后的短时模糊。
- gaze-coverage随时间、注视切换后恢复时间、ROI边缘未覆盖率。
- 非ROI和有效内容全图质量，报告局部收益的空间代价。
- 真实应用层字节、眼动反馈消息字节、有效眼动比例和GOP等待；后续网络实验再计传输协议和重传。

官方生成代码使用原图尺度32px Gaussian标准差。若复现该尺度，必须先在原始坐标中生成或按实际缩放变换核宽；不能直接在224图上使用32px。初期硬ROI的半径、形状和边界处理应预先固定，并进行半径敏感性分析，不能以“哪个框让本方法赢”来选择。

加权质量的基本定义：

```text
wMSE_t = sum_xy w_t(x,y) * mean_RGB[(I_t-Ihat_t)^2] / sum_xy w_t(x,y)
wPSNR = 10*log10(255^2 / mean_valid_frames[wMSE_t])
wSSIM = mean_valid_frames[sum_xy w_t*SSIM_map_t / sum_xy w_t]
```

所有方法使用完全相同的评价权重和帧集合，质量计算位于展示MP4编码之前。保留率继续标注30 dB/0.9阈值，并作为阈值指标解释，不称为互信息。

## 6. 实验划分与比较设计

### 6.1 数据划分

以原始视频/场景为最小分组单元，冻结标定与留出列表。同一原始视频的不同观察者、FV/TASK条件、不同裁剪片段不能跨两侧。VIRAT同一母视频裁剪片段需归到同组。

先根据场景、摄像机运动、注视离中心程度和源数据集分层，而不是按帧随机划分。若后续训练模型，额外划分训练集；不能把用于选择ROI尺度或超参数的内容称为最终测试集。

先按观察者聚合，再按视频聚合，避免长视频和高采样率观察者占据过高权重。置信区间按视频/原始场景分组重采样；不能把43×30条轨迹或数万帧都视作相互独立实验。

### 6.2 对照组

最低保留H.264、H.265、BiSTAR和Atlas四种方法，统一有效分辨率、帧率、源帧和实际码率口径。加入中心固定注视对照，检验真实眼动是否确实优于当前中心假设。

正式论文还应加入获得相同注视信息的传统ROI编码基线，以区分“所有注意编码方法都有的ROI优先级收益”与Atlas/重建机制的增益。ROI编码器的具体实现需另行核对接口后接入，当前项目尚未实现此强基线。

建议实验轴：

| 实验 | 输入/变量 | 目的 |
| --- | --- | --- |
| 主结果 | TASK真实眼动，独立视频留出，四方法实际码率匹配 | 验证真实关注区域保真 |
| 中心偏置 | 固定中心 vs 真实眼动 | 检查伪ROI收益能否迁移 |
| 观看条件 | FV与TASK分开 | 检查自由注意与监视注意差异 |
| 反馈时延 | 0/50/100/200 ms | 检查真实可用的过去注视是否足够 |
| mask周期 | GOP4/8/16，固定与自适应预算 | 检查注视移动与时序编码的折中 |
| 重建消融 | 相同码流/mask下MAE、插值、历史填充 | 分离模型对隐藏区域的贡献 |
| 覆盖机制 | 点距离选择 vs 完整ROI覆盖优先 | 检查此前四角误差问题是否缓解 |

主张只来自留出结果；若不能匹配码率或未超过基线，应保留负结果。本轮伪ROI中发现的64patch配置只能作为起始候选，不能固定为EyeTrackUAV2最优值。真实小ROI可能需要更少patch，注视快速移动时也可能需要更短mask周期。

## 7. 开发任务与验收顺序

以下为拟新增内容，尚未实现，不代表文件或命令已经可执行。

### 阶段A：数据盘点与刺激配齐

输出逐序列清单：源数据集、EyeTrackUAV2名称、原视频路径、源帧范围、实际帧数/FPS、观察者/条件、坐标文件、SHA256。先用DTB70同名序列试点，VIRAT裁剪和UAV123下载入口单独解决。

验收：至少两个视频成功配对；视频帧数和眼动frame_id范围一致；人工叠加确认无明显坐标偏移；明确哪些序列仍缺视频或映射。

### 阶段B：转换器与对齐检查

拟新增：

```text
src/datasets/eyetrackuav2.py
scripts/prepare_eyetrackuav2.py
configs/datasets/eyetrackuav2.yaml
datasets/manifests/eyetrackuav2.csv
datasets/annotations/eyetrackuav2_task.csv
```

实现13列解析、观察者/条件识别、帧号与时间映射、无效眼动规则、224尺度变换、ROI和轨迹导出。同步输出轨迹叠加视频、随机帧审计图、有效率表和对齐JSON。选择器输入必须与评价ROI分开存储，便于添加反馈时延。

验收：抽查起始、中间、末尾以及眼跳/边界帧；不得静默丢帧或用中心填补无效标签；同一视频各方法读取完全相同的源帧。

### 阶段C：小规模端到端验证

先选择2～3个已配齐视频、每个少量TASK观察者、单一码率和小候选集合，使用现有搜索框架验证全链路。两个以上独立原视频分别用于配置选择与留出，试点不报告统计显著性。

之后扩展到100/200/300 kbps，再根据实际可达范围扩展码率。先维持固定预算以分离因素，随后增加自适应和短GOP，不一开始展开所有参数的巨大笛卡尔积。

验收：四种方法均有匹配结果或明确不可达记录；生成ROI质量、覆盖率、注视轨迹和空间差值图；所有输入、控制注视和评价注视可追溯。

### 阶段D：多观察者与正式分组实验

重构视频帧和传统码流缓存，使同一视频的30条轨迹共享输入；分视频流式运行，避免当前按复合sequence_id重复装载整段视频造成内存膨胀。标定使用预先选定的观察者子集，最终冻结配置后在留出视频的更多观察者上评价。

验收：无场景/原视频泄漏；基线缓存不因观察者变化重复编码；输出按观察者和视频两级聚合；给出视频级区间和失败案例。

### 阶段E：论文级增强

补齐注视感知传统编码基线、反馈延迟、mask更新频率、有效分辨率/高分辨率敏感性。闭环远程操作效果仍需额外实验平台与受试者或控制器试验，EyeTrackUAV2本身不能代替。

## 9. 当前尚待解决的事项
