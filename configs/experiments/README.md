# Experiment modes

`smoke_test.yaml` creates a deterministic 224×224, 15 FPS source. `rd_sweep.yaml` and `matched_bitrate.yaml` compare H.264, H.265, per-frame BiSTAR, the GOP-stable H.264 patch atlas, and the focus-tracked video window using actual wire bytes. `ablation.yaml` compares `jpeg_patch` and `h264_atlas` for every selector and visible-patch budget, then evaluates the configured tracked-window sizes. `realtime.yaml` validates the real-time dependencies and records the atlas protocol settings; network shaping still requires an explicit interface and command.

The `bistar_tracked_window` method encodes a continuous small H.264/H.265 window centred on the per-frame visual focus, transmits its coordinates, decodes exclusively from wire bytes, and reconstructs the rest of the frame with a dynamic VideoMAE mask. Add an `roi` section with `annotations` and `coordinate_space` to use gaze annotations. If gaze is unavailable, focus falls back to the annotated ROI centre and then to `tracked_window.missing_focus_policy`. The stock single-video configurations use `frame_center` because that dataset has no gaze annotations.

`roi_config_search.yaml` searches codec and sparse-transport configurations on independently annotated task ROIs, selects configurations on `val`, and evaluates frozen winners on `test`. `roi_config_search_single_video.yaml` uses a temporal holdout for exploratory experiments on the current video. Both require complete ROI CSV annotations and preserve actual-rate match failures. See `docs/roi_config_search.md` for annotation, grids, plots, and provenance.
